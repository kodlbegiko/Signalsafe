SignalSafe 雙情境獨立任務測試

這一版不再要求受試者「進 Research Mode」。受試者看到的是正常 SignalSafe；主持人先提供一個合理的真實世界情境，再逐一給任務，觀察受試者是否能自己找到合適入口與完成目標。

A. 測試方法

每組任務都先建立「為什麼受試者此刻會打開 SignalSafe」的情境。情境只建立使用意圖，不直接透露應點哪一個功能。

任務獨立原則
T01–T08 可獨立完成。前一任務 FAIL 不代表下一任務不能測；需要特定資料狀態時，由主持人 reset、seed 或使用 deep link 建立起始狀態。

B. 情境一：老師要求進行防詐訓練

主持人念給受試者： 你是一名高中生。今天班導師告訴全班，最近很多學生收到假帳號通知、假購物訊息與假客服訊息，因此希望每個人使用 SignalSafe 練習自己的防詐判斷能力。老師只把 SignalSafe 網站交給你，沒有告訴你要按哪個功能。請依照你自己的理解使用這個網站。

T01｜找到訓練入口

請開始一次你認為適合這個情況的防詐訓練。

起始：Home / fresh-home

T02｜完成一次情境練習

請完成一次防詐情境練習。

起始：Home / fresh-home；不依賴 T01 成功。

T03｜找到自己的弱項

假設你已經使用 SignalSafe 練習一段時間，現在請找出自己目前最容易忽略哪一類風險。

起始：Dashboard / seeded-learning-history；不依賴 T02。

T04｜針對弱項繼續練習

請找出一個可以針對這個弱項繼續練習的方法。

起始：Dashboard / seeded-weakness-state；不依賴 T03。

C. 情境二：收到疑似帳號異常通知

主持人念給受試者： 你正在使用手機，突然收到一則看起來像是你常用服務官方帳號傳來的訊息：
「系統偵測到您的帳號有異常登入。為避免帳號停權，請於今天 18:00 前完成身分驗證。」

訊息下方附有一個「立即驗證帳號」連結。
你不確定這到底是真的通知，還是有人想騙你。這時你想到可以打開 SignalSafe。

安全邊界：這是合成訊息，不提供真實網址，也不要求受試者真的點擊、登入、輸入 OTP、密碼或金融資料。

T05｜開始處理現在的情況

請使用 SignalSafe 處理你現在遇到的情況。

起始：Home / fresh-home

T06｜找出第一件不應做的事

請找出你現在第一件應該避免做的事情。

起始：Emergency / fresh-emergency；可獨立測。

T07｜找到安全下一步

請找出目前比較安全的下一步。

起始：Emergency / fresh-emergency；可獨立測。

T08｜找到可信任的查證方式

請找出你可以怎麼確認這則通知是不是真的。

起始：Emergency / fresh-emergency；可獨立測。

D. 任務結果判定

PASS
獨立完成
PARTIAL
繞路／輕微提示後完成
FAIL
需直接操作提示或放棄
NOT ATTEMPTED
未執行

主持人一次只讀目前任務，不要說「點紅色按鈕」「去我的能力頁」「按我現在遇到可疑情況」等會透露 UI 解法的指令。

E. 測試場域

場域學校圖書館、自習室或其他安靜、不會被打擾的校內空間
形式一對一測試，每次一名受測者
設備統一使用 iPad Air，建議 iPadOS 16 以上，Safari 最新版本
網路穩定 Wi‑Fi；開始前確認正式網站可正常載入
時間每位約 30–45 分鐘，依個人操作速度而定
主持人坐在側後方觀察，不主動提示操作路徑

F. 招募受測者條件

  1. 16–18 歲，高中階段學生。
  2. 日常使用智慧型手機，並使用過 LINE、Instagram、遊戲、網路購物或其他數位服務。
  3. 能自行閱讀繁體中文，並能獨立操作網頁與填答題目。
  4. 未曾參與同版本 SignalSafe 正式研究測試；可曾使用一般模式或快速練習。
  5. 若本輪採 think-aloud，願意在主持人要求時說出自己的理解、判斷與操作想法。

G. Deep Link 與研究資料邊界

Usability task 可用匿名 participant context 開啟，但受試者看到的仍是正常 SignalSafe：

/prototype/?study=SST-V2&participant=U001&task=T05&route=home

Usability task 結果不得和正式 Pre-test / Training / Post-test 分數混成同一研究指標。正式 effectiveness research 仍走既有 Consent 與正式研究 pipeline。
