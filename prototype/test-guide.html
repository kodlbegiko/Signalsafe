SignalSafe V2.1 Usability Test Guide

Protocol：signalsafe-v2-usability-2026-08-16。這是產品可用性測試，不是教育成效證明。

Research Control一般 SignalSafe

A. 測試方法

一次只讀目前 Task。主持人不得說「點紅色按鈕」「去我的判斷紀錄」等會透露 UI 解法的提示。T01–T08 必須各自可執行；前一 Task FAIL 不得阻塞下一 Task。T03/T04 使用匿名、合成、deterministic fixture；fixture 只存在研究 session，不寫入一般 learner history。

B. 情境一：老師要求進行防詐訓練

主持人情境：老師希望學生使用 SignalSafe 練習防詐判斷，但不提示要點哪個功能。

T01 請開始一次你認為適合這個情況的防詐訓練。
Start: home / Setup: fresh-home
T02 請完成一次防詐情境練習。
Start: home / Setup: fresh-home
T03 假設你已經使用 SignalSafe 練習一段時間，現在請找出自己目前最容易忽略哪一類風險。
Start: dashboard / Setup: seeded-learning-history-v1
T04 請找出一個可以針對這個弱項繼續練習的方法。
Start: dashboard / Setup: seeded-weakness-source-v1

C. 情境二：收到疑似帳號異常通知

合成情境：訊息要求今日內登入驗證，否則停權。不得提供真實網址、OTP、密碼或金融資料。

T05 請使用 SignalSafe 處理你現在遇到的情況。
Start: home
T06 請找出你現在第一件應該避免做的事情。
Start: emergency
T07 請找出目前比較安全的下一步。
Start: emergency
T08 請找出你可以怎麼確認這則通知是不是真的。
Start: emergency

D. 任務結果判定

PASS：獨立完成。 PARTIAL：有繞路或中性提示後完成。 FAIL：需直接操作提示或無法完成。 NOT ATTEMPTED：未執行。

E. 測試場域

場域
學校圖書館、自習室或安靜校內空間
設備
iPad Air，Safari 最新版本
形式
一對一測試
主持人
側後方觀察，不主動提示操作路徑

F. 招募受測者條件

  1. 16–18 歲，高中階段學生。
  2. 日常使用智慧型手機與常見數位服務。
  3. 可自行閱讀繁體中文並操作網頁。
  4. 未參與同版本 SignalSafe 正式 usability task。

G. Deep Link 與研究資料邊界

Production 不使用 /prototype/ prefix。範例：

/?study=SST-V2&participant=U001&task=T03&route=dashboard&setup=seeded-learning-history-v1

建立 session context 後，participant/task/setup 會立即從網址移除；study context 只存在目前 tab/session。

每個 Task 記錄：task_id、result、started_at、ended_at、completion_time_ms、time_to_first_action_ms、first_action、help_requested、non_target_action_count、backtrack_count、path_taken、moderator_note。無法可靠自動取得的欄位標記 manual/null。

不得記錄姓名、學校、Email、電話、raw message、真實 URL、OTP、密碼或真實金融資料。Study Event Store 與 Product Learning Store 分離。一般 consumer UI 不顯示 Research/Pilot/受試者模式。

Human validation boundary

技術 Gate 全通過後再執行真人 Scenario A/B。未有真人證據前，只能說 implemented / technically verified / ready for human validation，不得說 users prefer、usability validated 或提升防詐能力。
