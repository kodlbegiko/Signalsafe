# 作業四：原型測試規劃與觀察表

## 文件狀態

本文件依 2026-07-31 FigJam 截圖整理。原始畫布已建立測試說明、主持人稿與三份觀察員表格，但大多數欄位仍未填寫。

> 這些內容是正式測試前的模板，不是已完成的測試結果。

## 4-1：原型測試說明文件

### A. 測試情境

建議主持人口頭說明：

> 你是一位 16–18 歲高中生，平常會使用社群、通訊、遊戲、票券、二手交易與活動報名服務。今天你會操作 SignalSafe 的短情境訓練。這不是考試，也不會要求你提供真實帳號、密碼或個人資料。我們希望觀察題目與流程是否清楚，而不是評價你本人。

### B. 測試任務

#### 任務 1：首頁與 90 秒快練

- 找到主要入口「開始 90 秒快練」
- 完成一組短情境
- 每題選擇最安全行動與一個最重要風險訊號

#### 任務 2：回饋與查證

- 閱讀題目解析
- 說出為什麼某個操作有風險
- 找到官方查證、封鎖、檢舉或求助路徑

#### 任務 3：個人盲點或學習紀錄

- 找到個人較常忽略的風險類型
- 說明自己是否看得懂圖表或回饋文字

#### 任務 4：急救模式

- 假設正在遇到可疑訊息
- 使用急救模式找出「先停止什麼」及「去哪裡獨立查證」
- 不上傳真實訊息、截圖或個資

### C. 測試場域

建議條件：

- 安靜、可錄製操作畫面但不錄製可識別個資的場域
- 使用受測者熟悉的手機或團隊測試裝置
- 網路環境需記錄；若產品支援離線，另行測試
- 主持人不得暗示正確答案
- 觀察者與主持人角色分離

### D. 受測者條件

- 16–18 歲高中階段學生
- 具智慧型手機、社群或通訊軟體使用經驗
- 非 SignalSafe 開發團隊成員
- 未完整接觸正式測試題庫
- 未成年參與須依場域要求完成同意流程

## 原型測試主持人稿

### 第一段：自我介紹

- 簡短介紹團隊與本次目的
- 說明本次測試用於改善產品，不是測驗個人能力
- 訪談與觀察內容應匿名處理

### 第二段：測試情境說明

> 接下來請你把自己想像成平常使用社群、遊戲或交易平台時，突然收到一則需要快速決定的訊息。請依你平常的方式操作。過程中可以把你想到的事情說出來。

### 第三段：開始任務

- 任務 1：進入並完成 90 秒快練
- 任務 2：閱讀回饋並找到查證方法
- 任務 3：查看個人盲點／學習紀錄
- 任務 4：完成急救模式

### 第四段：主持方式

- 不教受測者怎麼按
- 只在卡住時詢問「你現在在找什麼？」
- 鼓勵受測者以放聲思考方式說明判斷
- 紀錄錯誤、猶豫、誤解及自行修正

### 第五段：結尾

- 詢問其他想法與建議
- 再次強調資料匿名及研究限制
- 說明後續可能進行第 7 天短期複習測試

## 觀察員任務流程

觀察員應記錄：

1. 受測者的語言、表情、停頓、回頭及誤觸
2. 與主持人、介面及情境之間的互動
3. 哪些地方需要主持人介入
4. 哪些問題是介面、文字、題目或流程造成
5. 不應把個人姓名、學校或聯絡資訊寫入公開紀錄

每位觀察員各使用一份，建議欄位如下：

| 任務 4 |  |  |  |  |  |  |  |

### 欄位定義

- **喜歡：** 受測者明確表示喜歡或順利理解的部分
- **問題：** 卡住、誤解、按錯、找不到或答案歧義
- **建議：** 受測者直接提出的改進意見
- **點子：** 受測者提出的新功能或新情境
- **看見：** 觀察者看到、但受測者未主動說出的行為
- **其他回饋：** 不屬於前述類別的內容
- **照片／證據編號：** 只放匿名且經同意的操作證據編號，不放姓名

## 測試後彙整

每位受測者至少整理：

- 任務完成／未完成
- 完成時間與中斷狀況
- 需要提示的次數
- 最嚴重的理解問題
- 高風險誤操作
- 對 90 秒長度的感受
- 對回饋內容的理解
- 是否知道如何獨立查證
- 下一版必修與可延後項目

## 目前與正式研究的區分

### 8–12 人可用性測試

目的：

- 題目及介面是否看得懂
- 流程是否能完成
- 90 秒是否可行
- 選項是否有歧義
- 查證與求助路徑是否清楚

此階段不得宣稱教育成效。

### 20–40 人初步成效驗證

流程：

> 前測 → 訓練 → 立即後測 → 第 7 天延遲後測

主要指標：

- 新情境中的安全行動正確率

次要指標：

- 三分類 macro recall
- 目前較可信題誤判率
- 高自信錯誤率
- 風險訊號 precision／recall／F1
- 完成率及中位作答時間
- 第 7 天效果保留率
