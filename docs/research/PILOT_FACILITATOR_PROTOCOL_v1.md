# SignalSafe Pilot 主持人測試流程 v1

Protocol：`signalsafe-pilot-2026-08-13-v1`

## 目的

這一輪先驗證研究流程是否可靠、受測者是否理解題目與介面、資料是否可完整匯出。此 Pilot 不直接宣稱教育成效。

## 建議樣本

5–8 名符合招募條件的 16–18 歲高中階段學生。

## 場域與設備

- 學校圖書館、自習空間或等價的安靜校內空間。
- 一次一名受測者。
- 穩定 Wi-Fi。
- 統一 iPad Air + Safari；橫／直向由受測者自然選擇。
- 主持人坐在側後方，不操作受測者裝置。

## 開場口語稿

> 想像你平常會使用 LINE、Instagram、遊戲、購物平台和其他網路服務，也可能收到活動通知、帳號提醒、付款要求或陌生訊息。今天我們想了解高中生面對這些數位訊息時，會如何判斷情況並選擇下一步。請依照你當下最真實的直覺操作，不需要猜研究者想要的答案；這不是學校考試。

必要的外部研究說明、監護人／學校／倫理程序若適用，必須在進入網站研究確認前另外完成。

## 四項測試任務

1. 從 SignalSafe 首頁找到適合參與正式研究測試的入口，並開始測試。
2. 閱讀研究參與說明，依照自己的理解完成必要確認並進入正式測試。
3. 依照當下真實判斷，完成 Pre-test 8 題、Training 8 題與 Post-test 8 題。
4. 完成後查看結果頁，指出最需要加強的地方，並說明系統是否有幫助、哪裡需要修改。

## 分級提示

- Level 0：不提示。
- Level 1：只說「請再看看畫面上還有哪些選項」。
- Level 2：指出功能所在區域，但不告訴答案或具體選項。
- Level 3：為避免流程完全中斷，直接說明操作方式。

每項任務記錄最高提示 Level。Level 3 必須寫進觀察紀錄。

## 執行順序

1. 報到並確認招募條件。
2. 完成外部研究說明與任何必要同意程序。
3. 分配匿名 Participant ID。
4. 請受測者從 SignalSafe 首頁開始，不直接替他打開 Research Mode。
5. 觀察是否自行找到「參與 SignalSafe 研究測試」。
6. 讓受測者自行閱讀網站研究參與說明與完成確認。
7. 完成 Pre → Training → Post。
8. 完成後匯出研究 JSON。
9. 確認 JSON 使用正確 Participant ID、App/Study/Consent/Pilot protocol version，且 responses = 24。
10. 進行 3–5 分鐘訪談。

## 建議訪談題

1. 剛剛哪一題最難判斷？
2. 你判斷可疑訊息時，最先看什麼？
3. 有沒有哪個訓練提示讓你改變原本的判斷方式？
4. 哪個情境最像你平常真的可能遇到的？
5. 如果明天真的收到可疑訊息，你覺得自己會做什麼不一樣？

## 場次失敗條件

以下情況不要假裝資料完整：

- 受測者使用了別人的 Participant ID。
- 中途大量接受主持人答案提示。
- 題目或頁面無法載入且無法恢復。
- 24 題未完成卻被當成 completed session。
- JSON 匯出失敗或版本欄位不一致。

失敗場次保留事故紀錄，但不要直接混入正式成效分析。
