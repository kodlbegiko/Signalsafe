## 第一次導師會議｜2026-07-06

### 會議目的

- 說明 Samsung Solve for Tomorrow 複賽培力流程、時程與評分方式。
- 介紹設計思考、Double Diamond、POV、Persona 與原型驗證。
- 檢查反詐騙專案的題目、目標族群與現有產品。

### 導師核心診斷

團隊已先完成可操作的反詐騙訓練網站，技術進度不是最大問題；真正缺口是尚未充分證明：

1. 為什麼要做這個產品？
2. 為什麼選這個目標族群？
3. 使用者真正遇到什麼問題？
4. 為什麼互動訓練能解決？
5. 如何證明使用後有改變？

要求建立完整證據鏈：

> 真實問題 → 使用者研究 → 洞察 → 問題定義 → 解決方案 → 原型測試 → 成效與修正

### 主要風險

- 「詐騙」範圍過廣。
- 目標族群曾同時包含學生、中年與長輩。
- 產品先於研究完成，容易以團隊想像取代真實需求。
- 測驗分數不等於不會受騙。
- AI 判定有誤判、隱私與依賴問題。

### 第一次會議後任務

- 完成利害關係人地圖。
- 定義主要使用者與間接受益者。
- 訪談至少三位使用者。
- 蒐集二手資料與競品。
- 建立 POV、Persona、使用者旅程與前後測方式。

## 第二次導師會議｜2026-07-20

### 會議重點

- 檢視作業一、作業二與三位學生訪談。
- 確認人物誌、親和圖、POV 與 HMW 是否由真實資料推導。
- 檢查前測、訓練、後測原型與匿名資料。
- 處理核心目標族群與受訪樣本不一致。

### 會前完成

- 三位學生探索性訪談。
- U001–U003 匿名管理。
- 人物誌、親和圖、需求洞察與 HMW。
- 兩位完整前後測、一位僅前測。

### 核心發現

1. 學生不是完全沒有防詐意識。
2. 他們知道不提供個資、比對官方資料與詢問家人。
3. 真正缺的是系統化判斷及後續行動。
4. 使用者可能用「全部選可疑」通過測驗。
5. 抽象 `safe` 選項缺乏鑑別力。
6. 三分類與計時方式需修正。

### 會議後方向

- 目標族群需與研究資料一致。
- 日常訓練縮短。
- 改用有明顯風險／資訊不足／目前較可信。
- 安全行動改為官方查證、封鎖、檢舉、求助等具體選項。
- 家庭防詐只能列為待驗證的延伸影響。

## 第三次導師會議｜2026-07-29

### 一句話結論

> SignalSafe 已不缺功能原型；現在最重要的是固定目標族群、產品核心、日常流程、研究流程、指標與證據邊界，再用真實目標學生驗證。

### 凍結決策

| 項目 | 決策 |
|---|---|
| 目標族群 | 16–18 歲高中階段學生 |
| 產品定位 | 防詐決策訓練系統 |
| 模式主次 | 訓練核心、急救輔助 |
| 日常流程 | 最安全行動＋一個最重要訊號 |
| 研究流程 | 行動＋三分類＋多選證據＋自信 |
| 首頁主 CTA | 開始 90 秒快練 |
| AI | 後台輔助，不作前台最終判定 |
| 資料 | 匿名作答，聯絡資料分離 |

### 競品邊界

- 165、Whoscall、Google Messages、銀行與平台負責辨識、防護與官方查證。
- SignalSafe 負責情境反覆練習、個人盲點、遷移測試與保留測量。

### 驗證流程

1. 8–12 位 16–18 歲學生做可用性測試。
2. 修正介面與題意。
3. 20–40 位做前測、訓練、立即後測。
4. 第 7 天延遲後測。
5. 主要指標為新情境安全行動正確率。

### 重要證據邊界

- 功能 QA 不等於教育有效。
- 合成情境不包裝成官方真實案件。
- 90 秒與團隊門檻是待測假設，不是學界標準。
- 現階段不優先做 OCR、前台 AI、教師完整後台、排行榜或原生 App。

1. **第一次：** 從「先做產品」回到「先證明問題」。

3. **第三次：** 凍結規格，正式進入目標族群驗證。
